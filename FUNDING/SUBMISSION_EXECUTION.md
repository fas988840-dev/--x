# FactLedger — Funding Submission Execution

This is the pre-submission operating checklist for grants, accelerators, and investors. It separates project work that can be prepared in-repo from legal/account actions that require the project owner.

## Common submission package

Prepare and keep current:

- one-line positioning and problem statement;
- product description and architecture;
- public GitHub repository and current commit;
- production API URL and public demo URL when verified;
- 90–180 second product demo;
- measurable milestones and use-of-funds budget;
- verified traction metrics only;
- security posture and known limitations;
- team/founder information supplied by the owner;
- public Solana receiving wallet when the program permits wallet payout;
- entity/KYC/KYB information only through the program's secure channel;
- explicit IP ownership and dependency/license summary.

## Solana Foundation package

Use `FUNDING/SOLANA_FOUNDATION_DRAFT.md` as the narrative base. Before final submission, replace every placeholder or qualitative statement with sourced facts. Emphasize public-good benefit, inspectable evidence/provenance, open schemas/examples where feasible, measurable milestones, and a structured budget.

Do not imply that primarily commercial work is a pure public-good grant if the official program classifies it differently. Review the current program terms immediately before submission.

## Colosseum package

Use `FUNDING/COLOSSEUM_ETERNAL_DRAFT.md`, existing `GRANTS/colosseum-*.md` materials, and `DEMO.md` as the base. Submission proof should include a working Solana product, repository, concise founder/product video, demo, market thesis, and weekly progress evidence where required.

## Investor package

Prepare:

- `MARKET/ONE_PAGER.md`;
- product/demo links;
- architecture/security summary;
- market and buyer/user segments;
- design-partner pipeline;
- usage and revenue metrics when real;
- financing ask and use of funds;
- cap table / legal entity details supplied by the owner;
- data-room access for diligence.

## Binding-action boundary

The project owner must personally review and approve any submission containing certifications about identity, ownership, legal status, sanctions, taxes, KYC/KYB, banking, cap table, securities, SAFE/equity/token warrants, exclusivity, IP transfer, representations/warranties, or binding program terms. No assistant-generated document is a signature or legal acceptance.

## Funding receipt

If a program permits Solana payout, the designated public receiving address is documented in `FUNDING/RECEIVING_WALLET.md`. Confirm network, asset, address, and program instructions immediately before transfer. Never store a seed phrase, private key, recovery phrase, or signing secret in this repository.

## Submission gate

A submission is ready when the product claims are reproducible, demo links work, budget and milestones are specific, metrics are sourced, all required fields are populated, and the owner has completed any identity/legal attestations through the official application portal.
